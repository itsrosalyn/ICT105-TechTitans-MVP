# User Testing Plan

## 1. Testing Objective

We want to evaluate the usability, flow clarity, and overall user experience of the AttendQR prototype before Lab 14. Specifically, we aim to learn if students and lecturers can seamlessly navigate from the landing page, complete a QR-based attendance check-in, and understand their attendance history and class session metrics without assistance.

## 2. Test User Profile

| User Type | Number of Testers | Why This User Type Matters |
| --- | --- | --- |
| Target user (Students) | 5 | Primary end-users who need to complete quick, reliable 3-second check-ins during class sessions. |
| Admin/manager role (Lecturers) | 2 | Key stakeholders who set up class sessions, monitor attendance metrics, and verify student records. |

## 3. Testing Tasks
| Task ID | User Task | Related Requirement | Success Criteria | Observation Focus |
| --- | --- | --- | --- | --- |
| T01 | Open the homepage/landing page and explain what the system is for. | FR-01 | User correctly identifies AttendQR as a QR-based attendance tracking system. | Clarity of value proposition and CTA buttons. |
| T02 | Log in and submit an attendance check-in using the QR scanner. | FR-03, FR-10, FR-11 | User logs in and successfully checks into a class session within 10 seconds. | Camera permission handling, QR scanning speed, and location prompt clarity. |
| T03 | Search or filter attendance records by date or subject. | FR-05, FR-06 | User successfully filters past records to find a specific class session. | Filter placement, search responsiveness, and list layout usability. |
| T04 | View attendance details and check-in status for a specific class session. | FR-07, FR-08 |User easily reads their status (e.g., "Present", "Late", "Verified"). | Status badge color coding, timestamp legibility, and details layout. |
| T05 | Review the lecturer dashboard summary metrics (e.g., total present, class percentage). | FR-12 | User correctly interprets total class attendance rate and metric cards. | Visual chart clarity and metric summary organization. |

## 4. Testing Procedure
1. Introduce the test purpose.
2. Ask the tester to complete each task.
3. Do not guide unless the user is stuck.
4. Record completion, comments, and problems.
5. Ask final feedback questions.

## 5. Ethical Reminder
Do not collect unnecessary personal data. Explain that feedback is for class learning and prototype improvement.
